- [o] P4 — P1: session status는 session의 child가 끝났음을 보이고, session이나 연결이 끝나면 붙잡힌 입력을 지운다. 입력: sidecar가 session의 child가 끝났을 때 보내는 `exit` event, `connected: false`인 `connection` event. 동작: `exit`가 알 수 없는 분기로 떨어져 `sidecar.unknown`이 `warn`으로 기록됐고, page 상태는 끝을 보이지 않았다. session이나 연결이 끝난 뒤에도 `term.session.inputHeld`가 `{queued, held: true}`로 남았다. sidecar가 그때 `held: false`를 보내지 않기 때문이다. 기대: `term.session.exited`는 시작 시 `false`다. `exit`는 `exited`를 `true`로, `inputHeld`를 `null`로 만들고 `warn` 기록을 남기지 않는다. `state` event는 `exited`를 `false`로 만든다. `session` event는 `exited`를 `false`로 만들고 `inputHeld`는 그대로 둔다. 보존된 session은 입력이 붙잡힌 채로 다시 연결될 수 있고, sidecar는 바뀔 때만 `input_held`를 보내기 때문이다. `connected: false`인 `connection` event는 `inputHeld`를 `null`로 만든다. 마지막 frame은 화면에 남고, exit 뒤의 입력은 기존 오류 응답을 받는다. exit 때 card를 닫는 일은 이 항목에 포함하지 않는다. Red: `an exit event marks the session as ended and clears the held input without a warning`가 수정 전 코드에서 `AssertionError: a session has not ended before its exit event`(actual `undefined`, expected `false`)로 실패했고, `a connection that ends while input is held clears the held input`가 `the sidecar sends no held:false after a connection ends, so the page clears it`(actual `{queued: 8, held: true}`, expected `null`)로 실패했다. Green: 두 test가 통과하고, `node --test test/terminal.test.mjs`가 183개 중 183개 통과한다. `state` event는 재연결과 크기 변경 뒤에도 오므로 `inputHeld`를 지우지 않는다. `an exit event marks the session as ended and clears the held input without a warning`는 그 event가 지울 때 `a state event also follows a reconnect and a resize, and the session still holds the input`으로 실패했다(Red).
- [o] P3 — P1: session status는 sidecar가 붙잡고 있는 입력을 드러낸다. 입력: session의 대기 입력이 한도를 넘고 프로그램 출력 읽기가 멈추면(`held: true`) 그리고 읽기가 다시 시작되면(`held: false`) sidecar가 보내는 `input_held` event `{queued, held}`. 동작: event가 알 수 없는 분기로 떨어져 `sidecar.unknown`이 `warn`으로 기록됐고, 붙잡힌 상태는 보이지 않았다. 기대: 입력이 붙잡혀 있는 동안 `term.session.inputHeld`는 `{queued, held: true}`를 담고, 그 밖에는 `null`이다. `queued`가 음이 아닌 정수가 아니거나 `held`가 boolean이 아닌 event는 `terminal input failed: invalid input_held event from sidecar`로 거부하며, 어떤 status도 바꾸지 않고, 알 수 없는 event로 기록하지 않는다. 붙잡힌 상태는 오류가 아니므로 오류 경로로 보이지 않는다. Red: `test/terminal.test.mjs`의 `an input_held event publishes the held input and clears it when reads resume`가 수정 전 코드에서 `AssertionError: no input is held before the first input_held event`(actual `undefined`, expected `null`)로 실패했다. Green: 같은 test가 통과하고, `node --test test/terminal.test.mjs`가 181개 중 181개 통과한다.
