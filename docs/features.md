- [o] P1 — P1: A terminal plugin whose image region presents the frames of `@soksak/sidecar-alacritty` in the lease mode of core (F386) and reads the screen on request, beside the terminal plugin that stays the copy-mode baseline. P1-1 to P1-6 are complete.
  - [o] P1-1 — P1: The repository starts from the tree of the terminal plugin with the id `term`, the package `@soksak/plugin-term` 0.0.1, the commands, statuses and events named `term`, the sidecar `@soksak/sidecar-alacritty` `^0.0.1` and the region `view` with `present: "lease"`. Red: `test/manifest.test.mjs` failed on the manifests of the terminal plugin with the names `terminal`, the sidecar `@soksak/sidecar-vt-alacritty` and `present` `copy`. Green: it passes on the manifests of this repository, and `make test` and `make check` pass.
  - [o] P1-2 — P1: The sidecar sends a screen only on request, so the view takes the cursor, the caret and the scrollback of a frame from the `view` event of the sidecar (S1-7) and `term.screen` follows each read ([acceptance](spec/acceptance.md)). Red: `a view event publishes the cursor of its frame, moves the input-method caret and reports the scrollback` of `test/terminal.test.mjs` failed with a null caret and frame in `term.cursor`. Green: it passes, and a caret outside the grid is refused with an error; `make test` and `make check` pass.
  - [o] P1-3 — P1: Publish the repository as `soksak-app/plugin-term`, release 0.0.1 after the sidecar release 0.0.1, and add it to the registry. Result: the repository is public, core F393 declares it in the workspace registry, the release job of the CI run of P1-3-1 published `v0.0.1` with `soksak-plugin-term-0.0.1.tgz` after the sidecar `v0.0.1`, and the registry lists it (registry G74), whose `make build` downloads the release and checks its `sha256`.
    - [o] P1-3-1 — P1: The pre-push hook checks every commit of the pushed head on the first push of a repository, which has no origin/main. Red: `test/pre-push.test.mjs` failed with `ambiguous argument 'origin/main..<sha>'` for a first push. Green: it passes for a first push and for a push of an existing remote ref.
  - [o] P1-5 — P1: Release 0.0.2 with the sidecar `@soksak/sidecar-alacritty` `^0.0.2`, whose image surface draws on the GPU frame, and add it to the registry. Result: the release job of the push of this version published `soksak-plugin-term-0.0.2.tgz`, and the registry lists it.
  - [o] P1-6 — P1: Release 0.0.3 with the sidecar `@soksak/sidecar-alacritty` `^0.0.3`, whose frame draws without a GPU pass, and add it to the registry. Result: the release job published `soksak-plugin-term-0.0.3.tgz`, and the registry lists it (its G76).
  - [o] P1-4 — P2: Measure the CPU time of a frame against the terminal plugin with the same window and output. Result, on the published core 0.0.32 Tauri application with the sidecar `alacritty` 0.0.3 and the plugin `term` 0.0.3, in one window of 760 by 614 points that was not occluded, at load average 9 to 12 from other work on the machine: the total CPU of the application processes for a status line updated every 33 ms was 34.6 percent with the plugin `terminal` at 27.8 frames per second and 4.1 percent with the plugin `term` at 27.7 frames per second, which is 12.4 ms and 1.5 ms of CPU for a frame. For 20 rows rewritten every 33 ms it was 180.6 percent at 123.6 frames per second and 11.2 percent at 27.4 frames per second, which is 14.6 ms and 4.1 ms for a frame. The CPU and the frame counts come from separate runs of the same output, and captures of both terminals show the same rows.
